## 1. Матрица рисков

| Уровень риска | Категория | Описание риска | Последствия |
|---|---|---|---|
| **Критический** | Информационная безопасность | Файл `.env` с доменными паролями и токеном Telegram находится в рабочей директории и подготовлен к коммиту в Git (`Changes to be committed`) | Утечка учетных данных доменного администратора при `git commit` и пуше в удаленный репозиторий. |
| **Высокий** | Надежность / Stateful | Словарь `USER_ORIGINAL_OU` хранится в оперативной памяти процесса бота (`user_handlers.py`) | При перезапуске процесса бота теряется исходный OU сотрудников, находящихся в процессе выпуска сертификатов. |
| **Высокий** | Производительность | Блокирующий вызов PowerShell через `subprocess.run` в `pc_monitor_service.py` | Хотя вызовы обёрнуты в `asyncio.to_thread`, запуск нового процесса `powershell.exe` с таймаутом до 10 секунд создает высокую нагрузку на CPU при частых запросах. |
| **Средний** | Информационная безопасность | Фиксированный временный пароль `ASDfg123+` при сбросе | Все пользователи получают одинаковый временный пароль, что увеличивает риск несанкционированного входа до смены пароля пользователем. |
| **Средний** | Надежность | Отсутствие валидации сертификата контроллера домена (`validate=ssl.CERT_NONE`) | Риск атак типа Man-in-the-Middle (MitM) внутри локальной сети при выполнении StartTLS. |
| **Низкий** | Поддерживаемость | Неиспользуемые файлы (`services/db_service.py`, `services/print_service.py`) | Засорение кодовой базы неактивными заглушками. |

## 2. Анализ технического долга

1. **Отсутствие `.gitignore`:**
   В репозитории отсутствует файл `.gitignore`. В результате в индекс Git попали скомпилированные байткод-файлы `__pycache__/*.pyc`, служебные логи `logs/bot.log` и конфиденциальный файл `.env`.
2. **Хардкод путей организационных юнитов (OU):**
   Пути OU для выпуска сертификатов (`OU=notebooklenovo...`) и перемещения ПК захардкожены в константах файлов [user_handlers.py](file:///c:/Users/kbeletskiy/Documents/Kolins/handlers/user_handlers.py#L162) и [pc_handlers.py](file:///c:/Users/kbeletskiy/Documents/Kolins/handlers/pc_handlers.py#L25).
3. **Хранение состояния перемещения пользователей:**
   Словарь `USER_ORIGINAL_OU` в оперативной памяти должен быть заменен на персистентное хранилище (SQLite / Redis).
4. **Генерация паролей:**
   Отсутствует флаг `pwdLastSet = 0` (принудительная смена пароля при первом входе) и генерация уникального сложного пароля для каждого запроса.

## 3. Рекомендации по устранению и модернизации

### 3.1. Первоочередные действия (P0)
- [ ] Создать `.gitignore`, исключив `.env`, `*.pyc`, `__pycache__/`, `logs/`, `*.db`.
- [ ] Удалить `.env` и `*.pyc` из индекса Git (`git rm --cached .env`, `git rm -r --cached **/__pycache__`).
- [ ] Заменить фиксированный пароль `ASDfg123+` на криптографически стойкую генерацию (библиотека `secrets`) с флагом `pwdLastSet=0`.

### 3.2. Долгосрочные улучшения (P1 / P2)
- [ ] Задействовать `services/db_service.py` (SQLite) для надежного сохранения истории перемещений `USER_ORIGINAL_OU` и журнала действий.
- [ ] Вынести целевые пути OU (`TARGET_PC_OU`, `CERT_TARGET_OU`) в переменные окружения `.env`.
- [ ] Перевести сбор WMI-информации с вызова `subprocess.run(["powershell", ...])` на нативный Windows API или асинхронный WinRM-клиент.
